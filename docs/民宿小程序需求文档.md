## 1. 项目概述

### 1.1 背景

民宿行业高度依赖 OTA 平台（携程、美团、Airbnb），平台佣金高（10%~20%）、用户数据不属于商家、无法沉淀私域复购。越来越多单店民宿选择自建小程序，用内容种草 + 直接预订降低成本、沉淀会员。

### 1.2 产品目标

| 目标 | 衡量指标 |
| --- | --- |
| 降低获客与交易成本 | 小程序直订占比 ≥ 30%，平台佣金支出下降 |
| 提升内容转化 | 首页 → 房型详情转化率 ≥ 25%，详情 → 下单转化率 ≥ 8% |
| 提升复购 | 会员复购率 ≥ 15%，订阅消息触达打开率 ≥ 20% |
| 提升运营效率 | 房态维护、订单处理全部线上化，管家每日人力投入 ≤ 10 分钟 |

### 1.3 目标用户

| 角色 | 画像 | 核心诉求 |
| --- | --- | --- |
| 游客（未登录） | 被朋友圈/小红书/视频号内容吸引而来 | 快速判断「这家民宿值不值得住」 |
| 会员（已登录） | 有明确出行计划，关注价格与房态 | 选日期 → 看价格 → 快速下单 → 拿入住凭证 |
| 已入住/离店客人 | 已在店内或刚离店 | 入住指南、门锁密码、周边攻略、开发票、写评价 |
| 商家（店主/管家） | 1~3 人小团队 | 改房态、改价格、处理订单、退款、看数据 |

### 1.4 名词定义

| 名词 | 含义 |
| --- | --- |
| 房源 / 房型 | 一个可售单元，如「山景大床房」「整栋小院」 |
| 房态 | 某房型某日期是否可售（可售 / 已满 / 关闭 / 维修） |
| 间夜 | 住宿的最小计价单位，一晚一间 = 1 间夜 |
| 库存 | 某房型某日可售数量，整栋类房型库存固定为 1 |
| 订单状态机 | 订单从创建到完成/关闭的全流程状态流转规则 |
| 核销 | 客人到店后管家确认入住，订单进入「已入住」 |

## 2. 产品范围

### 2.1 一期范围（MVP，必须完成）

- 民宿介绍：图文详情、房型展示（按间预订 / 整栋包院两种售卖方式）、环境相册、周边游玩、真实评价
- 房态查询：日期选择、价格日历、剩余房量，两种售卖方式库存联动
- 在线预订：下单、微信支付、商家人工确认、订单列表/详情、取消退款、入住凭证
- 会员基础：微信登录、手机号绑定、我的页面
- 消息通知：预订成功、商家确认/拒单结果、入住提醒、退款结果（订阅消息）
- 商家后台（Web 或小程序管理端）：房态日历、价格日历、订单确认与处理、核销、退款

### 2.2 二期范围（P1）

- 优惠券、限时特惠、连住优惠、早鸟价
- 评价体系（下单后邀请评价、晒图、商家回复）
- 分享分销（分享海报、邀请有礼）
- 在线客服、常见问题、周边攻略
- 数据看板（订单、收入、入住率）

### 2.3 三期范围（P2）

- 积分商城、会员等级权益、储值卡
- 拼团 / 秒杀 / 直播挂载
- 多门店 / 多商家平台化（当前架构预留，不做实现）

### 2.4 明确不做（本期）

- 智能门锁对接、自助入住（确认不做，入住由管家现场接待、核销）
- 平台型多商家入驻与分账
- 发票自动开具（仅提供申请入口，人工处理）
- 小程序直播、短视频拍摄工具
- 复杂收益管理（动态定价算法）

### 2.5 前置资源与资质准备

当前尚无域名、服务器、微信商户号与小程序 AppID，需先启动以下准备，直接影响 M3 支付联调与 M6 上线：

| 资源 | 用途 | 获取方式 | 阻塞点 |
| --- | --- | --- | --- |
| 营业执照（个体工商户/企业） | 注册小程序、申请商户号的主体资质 | 当地市场监管部门办理 | 个人主体小程序**无法开通微信支付**，必须先办执照 |
| 小程序 AppID | 项目注册、开发者工具联调 | 微信公众平台注册并完成主体认证 | 无 AppID 只能先用测试号开发 |
| 微信支付商户号 | 在线收款、退款 | 微信支付商户平台申请，需营业执照、法人身份证、银行账户，并与 AppID 关联 | 无商户号无法联调支付 |
| 域名 + ICP 备案 | 小程序 request 合法域名（必须 HTTPS） | 购买域名 + 云服务器备案，约 1~2 周 | 无备案域名无法真机请求接口 |
| 云服务器 1核2G | 入口反向代理 + frp 中转 + 备案载体 | 腾讯云/阿里云轻量应用服务器 | 备案必须挂在云厂商 |
| SSL 证书 | HTTPS | 免费 DV 证书 + 自动续期 | 无证书小程序无法请求 |

过渡方案：资质办理期间，一期先实现「提交预订 → 商家后台人工确认 → 线下收款（转账/到店付）」，订单状态机与后台流程保持完整；商户号到位后仅替换支付环节，不改动业务结构。

#### 4.2.3 订单状态机

| 状态 | 触发条件 | 可执行动作 |
| --- | --- | --- |
| 待支付 | 提交订单成功 | 支付、取消 |
| 已关闭 | 待支付超 15 分钟 / 用户取消未支付 | 重新下单 |
| 待商家确认 | 支付成功（固定流程，不支持自动确认） | 用户：取消（按政策退款）、联系商家；商家：确认、拒单退款 |
| 待入住 | 商家在确认时限内确认 | 申请退款、联系商家、查看凭证、商家标记不可抗力取消 |
| 已入住 | 到店核销 | 申请退房、评价（离店后） |
| 已完成 | 离店日 12:00 自动完成 / 管家手动完成 | 评价、再次预订、开票 |
| 退款中 | 用户申请且需商家审核 | 撤销申请 |
| 已退款 | 商家同意 / 超时自动同意 | 无 |
| 已取消 | 商家拒单 / 确认超时自动退款 / 用户取消退款完成 | 重新下单 |

> 规则：
> 1. 不可跳状态；退款金额取「订单实付 − 已消费部分 − 违约金」，由后台可配置政策模板。
> 2. 人工确认时限默认 2 小时（后台可配 1~24 小时）；超时未处理自动全额退款并关闭订单，同时向商家后台强提醒。
> 3. 商家拒单必须填写原因，全额退款，建议附赠优惠券安抚（P1）。
> 4. 商家确认后进入「待入住」，此时用户取消按 4.2.4 取消政策执行。

#### 4.2.4 取消政策（默认方案，采用行业接受度较高的一档）

| 取消时间点 | 退款规则 |
| --- | --- |
| 入住前 3 天（72 小时）18:00 前 | 全额退款，免手续费 |
| 入住前 72 小时内至入住当日 12:00 | 扣除首晚房费（整栋包院按整栋首晚计），其余退还 |
| 入住当日 12:00 后取消或未入住 | 不予退款，可协商改期一次（视房态） |
| 商家拒单 / 商家原因无法接待 / 不可抗力（自然灾害、政策管控） | 全额退款，商家可赠券补偿 |

- 展示要求：房型详情、预订填单页、支付前、订单详情均需展示对应取消政策，避免争议。
- 退款到账：原路退回，1~3 个工作日；商家后台需记录退款审核人与时间。
- 押金：默认到店收取、离店退还，不纳入线上退款计算（待确认，见第 12 节）。

## 6. 核心数据模型（简表）

| 实体 | 关键字段 |
| --- | --- |
| RoomType 房型 | id、name、cover、images、area、beds、maxGuests、facilities、basePrice、stock、saleMode(按间/整栋)、unitRoomIds(包院包含房间)、status、sort |
| RoomInventory 房态 | id、roomTypeId、date、price、stock、status(可售/关闭/维修) |
| Order 订单 | id、orderNo、openid、roomTypeId、saleMode、checkIn、checkOut、nights、roomCount、guests、contactName、contactPhone、amount、paidAmount、deposit、couponId、status、confirmDeadline、confirmedAt、rejectReason、remark、arriveTime、createdAt、paidAt、canceledAt |
| Payment 支付 | orderNo、transactionId、amount、status、paidAt、refundAmount |
| Refund 退款 | orderNo、reason、amount、status、auditRemark、createdAt |
| User 用户 | openid、unionid、nickname、avatar、phone、memberLevel、points、createdAt |
| Coupon 优惠券 | id、type(满减/折扣)、threshold、value、validFrom、validTo、scope、receivedCount |
| Review 评价 | id、orderNo、openid、score、content、images、reply、createdAt |
| Content 内容 | type(banner/story/gallery/guide/faq/notice)、title、cover、body、sort、visible |

关键约束：

- 订单库存扣减需保证幂等，同一订单不重复扣减；支付回调、超时关单需加锁防并发。
- 房态库存按「房型 × 日期」维度存储，预订时校验连续日期区间可用。
- 两种售卖方式库存联动：整栋包院要求其包含的全部房间在该日期均可售；任一单间被订则该日期包院不可售；包院售出后其下所有单间该日期不可售。下单时需在事务内同时校验与扣减，避免并发超卖。
- 人工确认：订单落库时写入 `confirmDeadline`（默认支付成功 + 2 小时），定时任务每分钟扫描超时订单并自动退款关闭。
- 手机号、入住人信息属于个人敏感信息，需加密存储并遵守最小化采集原则。

## 9. 技术方案建议

### 9.1 总体架构（家用电脑自建服务端）

- 前端：Taro + React + TypeScript，一套代码输出微信小程序，后续可编译抖音/支付宝；状态管理用轻量方案（如 Zustand/自写 hooks），避免引入浏览器 DOM 依赖库。
- 后端：Node.js（NestJS）REST 接口，部署在家庭内网电脑上。
- 入口：微信小程序要求 HTTPS + 已备案域名，而家庭宽带通常无公网 IP、80/443 被运营商封锁，因此采用「云服务器做入口 + frp 内网穿透」：

```
微信小程序
   │ HTTPS(443)
   ▼
云服务器 1核2G（备案域名、nginx、SSL 证书）
   │ frps
   ▼ 加密隧道（家宽主动外连，无需公网 IP）
家用电脑（frpc）
   ├─ API 服务 Node/NestJS :3000
   ├─ PostgreSQL 16        :5432（仅内网）
   ├─ Redis 7（可选）       :6379（仅内网）
   └─ 备份任务（pg_dump）
图片/视频 → 对象存储 COS/OSS + CDN（不放家里）
```

- 支付：微信支付 JSAPI，需商户号与支付目录配置；回调做验签与幂等。
- 消息：微信订阅消息（模板在后台配置），商家通知走公众号/短信/后台红点。
- 图片与内容：图片存对象存储 + CDN，数据库只存 URL；富文本内容后台编辑。
- 管理端：优先做 H5 管理端（复用 Taro H5 或独立 React 项目），可先用简易后台保证房态/订单可运营。

### 9.2 数据库选型

| 方案 | 适用性 | 说明 |
| --- | --- | --- |
| **PostgreSQL 16（推荐）** | ★★★★★ | 订单与房态需要强事务和行锁，`SELECT ... FOR UPDATE`、唯一约束直接满足防超卖；JSONB 存房型设施、富文本块；`generate_series` 便于生成 90 天价格日历；单机资源占用可控 |
| MySQL 8.0 | ★★★★☆ | 能力等价，若团队更熟悉 MySQL 生态可直接采用 |
| SQLite | ★★☆☆☆ | 仅适合 M0 演示；C 端与商家后台并发写入、备份迁移都受限，不建议作为正式库 |

配套与参数建议：

- Redis 7：缓存房态日历 / 首页内容 + 15 分钟未支付关单的延时任务，可选；不部署则用定时任务 + 数据库原子更新替代。
- 硬件：4 核 8G、SSD 100G 起；PostgreSQL `shared_buffers` 1~2G，`max_connections` 100。
- 关键约束：房态表对 `(roomTypeId, date)` 建唯一索引；订单号唯一索引；库存扣减使用 `UPDATE ... SET stock = stock - 1 WHERE stock > 0` 或行锁，保证并发不超卖；支付回调与关单以订单号做幂等键。

### 9.3 备份与恢复

- 每日 02:00 执行 `pg_dump` 全量备份 + WAL 归档，本地保留 7 天、异地保留 30 天（OSS/网盘）。
- 备份文件异地上传，避免家庭断电、硬盘损坏导致数据全丢。
- 每季度做一次恢复演练，验证备份可用。
- Redis 数据可丢（仅缓存）；图片依赖对象存储自身多副本与版本管理。

### 9.4 家用电脑运行保障

- 关闭系统休眠与自动更新重启；Docker 容器设置 `restart: always`，开机自启。
- 建议配 UPS，防止断电导致数据库损坏（PG 可承受异常断电，但仍需 UPS 兜底）。
- 家用上行带宽有限，图片/视频一律走 CDN，API 响应控制体积。
- 增加外网监控探活（如 UptimeRobot），异常时自动切换到云服务器上的静态降级页并告警。
- 仅对外暴露 443，PostgreSQL/Redis 端口不映射到公网，只允许 Docker 内网访问。
- 运行环境：Windows 用 Docker Desktop + WSL2；Linux 用 Docker Compose，更推荐后者用于长期运行。

### 9.5 部署组件清单

通过一份 `docker-compose.yml` 编排：`nginx`（或 Traefik 入口）、`api`（Node/NestJS）、`postgres`、`redis`（可选）、`frpc`、`backup`（定时备份）。云服务器侧单独运行 `frps` + nginx + 证书自动续期。

### 9.6 合规提醒

- 域名需完成 ICP 备案，微信小程序「服务器域名」只能填写已备案的 HTTPS 域名。
- 手机号、入住人信息等个人敏感字段加密存储，遵循最小化采集原则，隐私政策中明确告知存储位置与保留期限。
- 家用服务器属于自行处理个人信息，需做好访问日志与权限隔离，避免数据库直接暴露公网。

## 12. 待确认问题

已确认决策（2026-11-13）：

1. **人工确认**：支付成功后必须商家确认，默认 2 小时内处理，超时自动全额退款关单。
2. **取消政策**：入住前 72 小时免费取消；72 小时内至入住当日 12:00 扣首晚房费；当日 12:00 后不可退；商家原因/不可抗力全额退。
3. **房型售卖**：按间与整栋包院两种并存，库存双向联动。
4. **智能门锁/自助入住**：不做，入住由管家现场接待并核销。
5. **基础资源**：暂无域名、服务器、微信商户号、小程序 AppID，按 2.5 节清单准备。

仍需确认：

1. 是否需要押金？线上收取还是到店收取（暂按到店收取、离店退还设计）？
2. 目标上线时间与首期预算范围。
3. 民宿是否已有个体工商户/企业营业执照（决定 AppID 与商户号能否办理）。
